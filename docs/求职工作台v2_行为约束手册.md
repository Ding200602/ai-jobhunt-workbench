# 求职工作台 M2 · 行为约束手册

> 版本：v1 · 2026-09-06
> 适用：所有通过 MCP 接入本平台的 AI 客户端
> 核心原则：**真实、人味、安全、可量化**

---

## 一、简历修改规则

### 1.1 真实性红线（绝对禁止）

- ❌ 编造实习公司名、实习岗位名、实习时长
- ❌ 编造获奖/证书/GPA/排名
- 可接受的"放大"：
  - 课设项目 → 包装为"个人项目经历"（不写课程名）
  - 个人小程序/GitHub 项目 → 写成完整项目经历
  - 自媒体/技术文章 → 写为"技术内容创作"

### 1.2 技能表述标准

| 表述 | 含义 | 使用条件 |
|------|------|----------|
| 熟练 | 能独立完成相关任务 | 有实际使用经验，能应对面试追问 |
| 精通 | 深入理解底层原理 | 有源码阅读/二次开发经验 |
| 了解 | 学过/看过，但无法独立实现 | 仅用于不关键的辅助技能 |

### 1.3 语气标准（去 AI 味）

- ✅ 短句为主，偶尔省略主语
- ✅ 有个人思考："这个方案我觉得比 XX 好，因为…"
- ✅ 带点自嘲/吐槽："之前踩了个坑，后来查文档才发现…"
- ✅ 数据量化："做了三次 A/B 测试，转化率从 5% 提到 8%"
- ❌ 模板腔："基于以上分析，我深信…"
- ❌ 空洞形容词："非常、极其、绝对"
- ❌ 被动句式："被推荐、被认可、被认可"
- ❌ 套话结尾："期待与您进一步交流"

## 二、话术规则（跟 HR 聊天）

### 2.1 打招呼（首次发起对话）

**场景**：岗位列表页，点击"立即沟通"

```
HR，您好，我对您发布的[岗位名称]很感兴趣，我是[专业]在读，
做过[1-2个真实项目，用一句话描述]。方便发一下简历吗？
```

**要求**：
- 不要"贵司""非常感谢您的关注"这种模板腔
- 不要发长段自我介绍，HR 没耐心看
- 一句话说明你是谁 + 为什么适合

### 2.2 回复简历请求（HR 说"发简历"）

```
好嘞，发一份简历给您，您看看是否合适～
（同时上传简历附件）
```

**要求**：
- 语气轻松，不卑不亢
- 不要附长段文字，HR 只关心简历本身

### 2.3 面后跟进

**面后 1 天**：

```
您好，昨天的面试辛苦您了。回去后我仔细想了想您提到的[某个面试问题]，
补充了[具体想法]，不知道有没有参考价值？另外想问下后续的进展大概是怎样的节奏？
```

**要求**：
- 提到具体的面试细节（证明真去面试了）
- 不要催得太急，"不知道有没有参考价值"留余地
- 自然地问进度，不是直接问"过了没"

### 2.4 催面

```
打扰一下，之前聊过[岗位名称]的事，不知道流程走到哪一步了？
如果需要我补充什么材料随时说～
```

## 三、公司过滤规则

### 3.1 必跳（直接跳过，不投）

| 条件 | 判断方法 |
|------|----------|
| 注册资本 < 50万 且 参保人数 < 10 | 企查查 API |
| 近 6 个月有 3 条以上"欠薪"相关投诉 | 看准网/脉脉 |
| 岗位描述与 JD 严重不符（挂羊头卖狗肉） | 人眼 + AI 对比 |
| 招聘人数 <= 3 且薪资范围极宽（如 2k-10k） | 薪资合理性检查 |
| 公司名查不到工商信息 | 企查查 API |
| 已有 HR 在脉脉/知乎吐槽该司 | 搜索引擎 |

### 3.2 标红警告（可投但需用户二次确认）

| 条件 | 判断方法 |
|------|----------|
| 参保人数 < 50 或 成立时间 < 1 年 | 规模偏小 |
| 岗位描述模糊，技能要求不匹配 | 匹配度 < 60% |
| 薪资低于目标岗位均值 20% 以上 | 薪资对比 |
| 公司只有官网无招聘账号/社交媒体 | 信息量少 |

## 四、到手薪资计算引擎

### 4.1 输入参数

| 参数 | 说明 | 默认 |
|------|------|------|
| 税前月薪 | JD 给出的月薪范围，取中位数 | 用户输入 |
| 城市 | 社保比例按城市计算 | 用户提供目标城市 |
| 五险一金比例 | 按当地标准自动计算 | 自动 |

### 4.2 计算逻辑

**城市 A 标准**（参考）：
- 养老 8%、医疗 2%、失业 0.5%（合计个人 10.5%）
- 公积金 7%（可调整）
- 到手 = 税前 × (1 - 17.5%)

**城市 B 标准**：
- 养老 8%、医疗 2%、失业 0.3%（合计个人 10.3%）
- 公积金 5%
- 到手 = 税前 × (1 - 15.3%)

**城市 C 标准**：
- 养老 8%、医疗 2%、失业 0.5%（合计个人 10.5%）
- 公积金 8%
- 到手 = 税前 × (1 - 18.5%)

> 各城市五险一金比例以当地人社部门当年公布为准，计算前先查参数。

### 4.3 年终奖估算

| 条件 | 估算方式 |
|------|----------|
| JD 写了"13-15薪" | 取中位数（14薪），年终奖 = 1个月税前 |
| JD 写了"年终奖"但没给数字 | 估算为 1 个月税前 |
| JD 没提年终奖 | 按 0.5 个月税前保守估算 |

### 4.4 总包计算

```
总包 = 到手月薪 × 12 + 年终奖估算 + 餐补/交通补/房补（如有）
```

## 五、岗位筛选流程

```
用户输入岗位关键词 + 城市 → 抓取 JD 列表
       ↓
逐岗检查：
  1. 公司验真（企查查）→ 必跳/标红/通过
  2. 薪资合理性 → 标红 if 不合理
  3. 匹配度计算 → 低于阈值跳过
  4. 到手薪资计算 → 记录
       ↓
输出：通过名单（可投）+ 标红名单（需确认）+ 已跳名单
       ↓
用户确认后 → 执行投递
```

## 六、规则执行方式

所有规则以**结构化 JSON/YAML** 格式存储在平台侧，
每个 MCP 客户端接入时获取规则文件，作为 AI 行为的硬约束。
规则文件路径由 MCP 协议层提供，AI 不得修改。

规则更新流程：
1. 平台侧修改规则文件
2. 通知已接入的 MCP 客户端拉取新版本
3. 客户端下次调用前重新加载规则
