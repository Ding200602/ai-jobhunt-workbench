# AI 求职工作台（jobbot）

让任意 AI 助手接上就能跑的全流程求职工作台：**改简历 → 搜岗位 → 剔坑岗 → 背调公司 → 批量投递 → HR 沟通 → 约面试**。

设计理念：工作台只负责"能干活的引擎 + 可视化面板"，大脑由外部 AI（Marvis / 任意 MCP 客户端 / CLI Agent）担任——换一个 AI 接上来照样能用。

## 架构

```
外部 AI（大脑：拆解任务 / 决策 / 生成内容）
        │  驱动
        ▼
┌─────────────────────────────────────────────┐
│ jobbot 工作台                                │
│  bot.py        投递引擎：DrissionPage 控      │
│                独立 Edge 实例执行浏览器动作     │
│  flow.py       7 阶段流程状态机（SSE 推送）    │
│  ── 采集层（统一 schema 输出）──               │
│  search_channels.py   多平台岗位搜索插件框架    │
│  scatter_channels.py  零散渠道采集器            │
└─────────────────────────────────────────────┘
        │ 事件流
        ▼
  可视化面板（步骤 / 日志 / 截图实时广播）
```

## 核心亮点：零散渠道岗位采集

好岗位往往不在招聘软件上，而是散落在学校官网、企业公众号、省级就业平台、社区汇总表里。`scatter_channels.py` 用"**一个源 = 一个函数 + 字段映射**"的插件式设计采集这类分散信息：

| 来源 | 内容 |
|---|---|
| 省级就业服务平台 · 校招公告 | 各高校就业网发布的校招简章（聚合于省平台） |
| 省级就业服务平台 · 单位直发 | 企业自主发布的零散岗位 |
| 省级就业服务平台 · 双选会 | 校园招聘会/双选会排期 |
| 社区维护汇总表 | GitHub 上的校招入口 md 表格 |

实测一轮可捞回 **694 条**（高校校招公告 400 + 单位直发岗 165 + 双选会排期 100 + 校招入口 29），自动去重、按来源分类后与平台搜到的岗位合成一张总表，可按薪资/城市筛选。

平台搜索侧由 `search_channels.py` 负责：每个招聘平台是一个插件（搜索 URL 模板 + 列表定位符 + 字段映射 + 翻页方式），统一输出 schema。

## 统一岗位 schema

```json
{
  "source": "zhaopin | province_campus | campus2026 | ...",
  "kind":   "job（具体岗位） | entry（校招入口/公司级）",
  "job_name": "", "company": "", "city": "",
  "salary": "", "meta": "学历/经验标签",
  "date": "", "link": "", "raw": ""
}
```

## 文件说明

```
bot.py                 投递工作台核心引擎（DrissionPage + 事件总线 Hub）
flow.py                求职全流程 7 阶段状态机（信息收集→简历→清洗→导入平台→搜岗→投递→约面）
search_channels.py     多平台岗位搜索采集器（插件式渠道注册表）
scatter_channels.py    零散渠道采集器（官平台聚合/单位直发/双选会/社区汇总表）
docs/                  方法论文档：架构蓝图 / 行为约束 / 求职通 skill / 实操手册 / 全环节闭环工作流
```

## 运行

```bash
pip install DrissionPage
python bot.py    # 启动工作台引擎（自动拉起独立 Edge 实例）
```

- 岗位数据（JSON/Excel 产出物）不含在本仓库，跑采集器即可自行生成
- 登录态使用独立浏览器 profile（`edge_profile/`），与日常浏览器隔离
